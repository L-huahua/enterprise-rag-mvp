# 一页说明：CodingAgent + 视频剪辑 Agent

## 架构

```
用户需求（自然语言）
      │
      ▼
┌─────────────────────────┐        ┌──────────────────────────┐
│ 阶段一 CodingAgent      │        │ 工具层（workspace 沙箱） │
│  loop.py 主循环          │───────▶│ list/read/write_file     │
│  ├ 4 道执行护栏          │        │ run_python / check_python│
│  ├ llm.py 重试+主备切换  │        │ finish（触发产物校验）   │
│  └ tracing.py 证据落盘   │        └──────────────────────────┘
└─────────────────────────┘
      │ 自主生成
      ▼
┌─────────────────────────┐
│ 阶段二 VideoAgent       │  analyze → analysis.json
│ （Agent 自己写的代码）   │  plan    → timeline_v1/v2.json
│  标准库 + ffmpeg CLI     │  render  → output_v1/v2.mp4
└─────────────────────────┘
```

设计要点：
- **确定性优先**：视频处理直接调 ffmpeg CLI，不用 moviepy，避免版本 API 差异
- **契约先行**：时间线 JSON 结构固定，追加修改只改参数、不动代码
- **证据驱动**：每次运行自动产出 `runs/<run_id>/` 四件套，交付材料不靠回忆补录

## 已知问题

1. **长文件读取仍有分页上限**（约 12000 字符 / 400 行）：`read_file` 已从「4000 字符硬截断」改为按行分页并给出续读行号，10KB 级源码可一次读完
2. **步数预算曾被耗尽**：前两次跑完产物却没来得及 `finish`；已加「剩 2 步强制收尾」告警并上调上限至 24
3. **无沙箱隔离**：代码在本机直接执行，只有 workspace 路径越界防护
4. **素材分析只到元数据层**，没有画面内容理解，剪辑决策缺少语义依据
5. **弱模型易过度探索**：`glm-5.3-flash` 在任务边界模糊时会反复验证
6. **workspace 保留历史探测脚本**（`find_ff.py`、`make_sample.py` 等），阶段二那次的 `meta.json` 产物清单因此混入无关文件，需按需过滤
